# AMUGOTO

아무것도 몰라도, 안전하게 앱은 만들 수 있게.

AMUGOTO는 비개발자와 초기 기획자가 `Lovable`, `v0`, `Replit Agent`, `Cursor`, `Claude Code` 같은 AI 앱 빌더와 코딩 에이전트를 쓰기 전에, 위험한 요구사항을 먼저 점검하고 안전한 제작 주문서로 바꿔주는 사전 안전 레이어입니다.

## 무엇을 해결하나요?

AI 앱 빌더는 자연어만으로도 앱을 만들 수 있다고 말하지만, 실제로는 첫 프롬프트에서 이미 중요한 보안, 개인정보, 권한, 결제 설계가 들어갑니다.

예를 들어 이런 요청은 위험할 수 있습니다.

- 고객 카드번호를 직접 저장하고 싶다
- 관리자 페이지에서 모든 고객 정보를 한 번에 보고 싶다
- 로그인 없이 URL만 알면 운영 화면에 들어가게 하고 싶다
- 민감한 개인정보를 필요 이상으로 오래 보관하고 싶다

AMUGOTO는 이런 요구를 먼저 감지하고:

- 어떤 점이 위험한지 설명하고
- 더 안전한 앱 요구사항으로 다시 쓰고
- 선택한 툴에 맞는 실행용 프롬프트를 만들고
- 출시 전 체크리스트까지 묶어줍니다

## 제품 전략 고도화

AMUGOTO는 단순히 `초보자가 바로 떠올릴 수 있는 위험한 요청`만 잡는 도구로 끝나지 않으려 합니다.

다음 단계의 목표는 `개발자도 놓치기 쉬운 설계 단계 보안 실수`를, 앱을 만들기 전에 먼저 막는 것입니다.

특히 아래 같은 리스크를 더 깊게 다루는 방향으로 확장합니다.

- 다른 사람 데이터에 접근할 수 있는 객체 단위 권한 누락
- 일반 사용자가 관리자 기능을 실행하는 기능 단위 권한 누락
- `role`, `ownerId`, `price`, `status` 같은 숨은 필드 조작
- 예약, 결제, 쿠폰, 승인 흐름의 비즈니스 로직 남용
- 대량 호출로 비용과 자원을 태우는 흐름
- 외부 API, 웹훅, 결제 응답을 과신하는 설계
- 사용자 입력 URL을 서버가 직접 읽는 SSRF성 흐름
- 지점, 업체, 테넌트 간 데이터 분리 실패
- AI 코딩 툴이 외부 문맥을 그대로 믿는 프롬프트 인젝션성 흐름

즉, AMUGOTO의 방향은 `위험한 문장 감지기`가 아니라:

> AI가 코드를 만들기 전에, 위험한 설계를 먼저 멈추는 secure design copilot

이 되는 것입니다.

## 현재 제품 흐름

1. `홈`
   제품 소개와 진입 경로를 보여줍니다.
2. `바로 시작`
   사용자가 직접 앱 아이디어와 상세 조건을 입력합니다.
3. `업종별 예시`
   실제 업종 예시를 선택해 시작 화면으로 바로 가져옵니다.
4. `결과`
   위험 분석, 안전한 대안, 출시 준비도, 툴별 프롬프트, 최종 주문서 패키지를 제공합니다.

## 현재 포함된 핵심 기능

- 위험한 요구 자동 감지
- 쉬운 설명으로 다시 풀어주기
- 안전한 앱 요약 생성
- MVP 범위 / 제외 기능 분리
- 허용 데이터 / 차단 데이터 분리
- 관리자 권한 가이드
- 전후 비교 뷰
- 출시 준비도 점수
- 툴별 프롬프트 생성
- 최종 주문서 패키지 한 번에 복사

## 앞으로 강화할 출력물

이 전략에 맞춰 결과물도 더 구체화할 예정입니다.

- 역할별 권한 매트릭스
- 클라이언트가 보내면 안 되는 금지 필드 목록
- 예약/결제/승인 흐름용 남용 방어 규칙
- 외부 API / 웹훅 신뢰 규칙
- AI 코딩 툴 사용 시 검토가 필요한 실행 제약

## 타깃 사용자

- AI로 예약, 결제, 운영용 앱을 만들고 싶은 비개발자
- 1인 사업자, 소상공인, 운영자
- 제품 요구사항은 막연하지만 빠르게 프로토타입을 만들고 싶은 사용자
- AI 코딩 툴을 쓰기 전, 무엇을 요청해야 안전한지 모르겠는 사용자
