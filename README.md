# AMUGOTO

아무것도 몰라도, 안전하게 앱은 만들 수 있게.

AMUGOTO는 `Lovable`, `v0`, `Replit Agent`, `Cursor`, `Claude Code` 같은 AI 앱 빌더와 코딩 에이전트를 쓰기 전에, 위험한 요구사항을 먼저 점검하고 안전한 제작 주문서로 바꿔주는 `pre-build secure design copilot`입니다. 비개발자의 막연한 앱 아이디어를, 개발팀이 바로 구현하고 검증할 수 있는 안전한 요구사항으로 번역하는 데 초점을 둡니다.

## 핵심 요약

### 30초 요약

- `트랙 적합성`
  - `Business & Applications`에 맞는 실제 동작 제품입니다.
- `누구를 위한가`
  - AI로 예약, 결제, 운영용 앱을 만들고 싶은 비개발자와, 그 결과를 실제로 구현·검증해야 하는 개발팀
- `어떤 문제를 푸는가`
  - 비개발자는 코드를 못 짜서가 아니라, AI에게 안전한 요구사항을 못 써서 위험한 앱을 만들기 쉽습니다.
- `어떻게 푸는가`
  - 막연한 아이디어를 입력하면, AMUGOTO가 위험 요소와 숨은 설계 리스크를 분석하고 안전한 앱 주문서, 툴별 프롬프트, 심층 보안 리포트, 역할별 실행 티켓까지 생성합니다.
- `왜 AI가 핵심인가`
  - 기본 분석은 `gemini-3-flash-preview`, 심층 보안 리포트는 `gemini-3-pro-preview`를 사용해 아이디어를 구조화된 보안 설계 산출물로 바꿉니다.
- `현재 데모 범위`
  - 홈, 시작 화면, 업종별 예시, 역할별 주의사항, 기본 분석 결과, 심층 보안 리포트, PDF 저장, 개발자 실행 티켓 생성까지 동작합니다.

### 심사 기준 한눈에 보기

- `Problem & Market Clarity`
  - 첫 진입 사용자는 `AI로 예약/결제 앱을 만들려는 비개발자`이고, 실제 산출물을 소비하는 2차 사용자는 `개발자·QA·운영`입니다.
  - 문제는 `AI에게 무엇을 어떻게 요청해야 안전한지 모르고`, 개발팀은 그 결과를 구현 가능한 보안 요구사항으로 다시 정리해야 한다는 점입니다.
- `Product Completeness`
  - 입력 → 기본 분석 → 안전한 주문서 → 심층 보안 리포트 → 역할별 실행 → 티켓 복사/PDF 저장까지 한 흐름이 연결됩니다.
- `AI Integration`
  - AI가 없으면 제품이 성립하지 않습니다.
  - 단순 요약이 아니라 `위험 감지`, `설계 재작성`, `리포트 생성`, `실행 티켓 생성`이 모두 AI 중심입니다.
- `Business Viability`
  - 기본 분석은 무료, 심층 보안 리포트와 팀 전달용 산출물은 유료화하기 좋은 구조입니다.
- `Demo & Presentation`
  - 3분 안에 `위험한 원문 → 안전한 주문서 → 심층 보안 리포트 → 개발 티켓`까지 보여줄 수 있게 설계했습니다.

## 무엇을 만드는 프로젝트인가

AMUGOTO는 단순한 “위험한 문장 감지기”가 아닙니다.

- 비개발자와 초기 기획자가 막연한 앱 아이디어를 입력하면
- AI가 위험 요소와 숨은 설계 리스크를 먼저 짚고
- 더 안전한 요구사항, 실행 프롬프트, 역할별 실행 가이드, 개발자 실행 티켓까지 정리해 주는 제품입니다

특히 아래처럼 `개발자도 놓치기 쉬운 설계 단계 보안 문제`를 코드 생성 전에 먼저 드러내는 데 초점을 둡니다.

- 객체 단위 권한 누락(BOLA / IDOR)
- 관리자 기능 경계 누락
- `role`, `ownerId`, `status`, `price`, `tenantId` 같은 클라이언트 제어 필드
- 예약 / 결제 / 쿠폰 / 승인 흐름의 남용과 비용 폭탄
- 웹훅, 결제사, 업로드 URL, 외부 API 과신
- SSRF성 URL fetch
- 멀티테넌트 / 지점 분리 실패
- AI 코딩 툴이 읽어온 외부 문맥으로 인한 prompt injection 리스크

## 왜 지금 필요한가

AI 앱 빌더와 코딩 에이전트는 자연어만으로 빠르게 프로토타입을 만들 수 있게 해주지만, 실제로는 첫 프롬프트 단계에서 이미 다음이 결정됩니다.

- 어떤 데이터를 받는지
- 누가 무엇을 볼 수 있는지
- 결제를 어디서 처리하는지
- 관리자 화면을 어떻게 통제하는지
- 외부 API와 웹훅을 얼마나 믿는지

즉, `코드가 생성되기 전의 설계 문장`이 이미 보안 품질을 크게 좌우합니다.  
AMUGOTO는 바로 이 지점에 들어가서, 위험한 요구를 먼저 안전한 요구로 바꾸는 사전 안전 레이어 역할을 합니다.

## 누구를 위한 제품인가

### 1차 사용자

- AI로 예약, 결제, 운영용 앱을 만들고 싶은 비개발자
- 1인 사업자, 소상공인, 운영자
- 요구사항은 막연하지만 빠르게 프로토타입을 만들고 싶은 사용자
- Lovable, v0 같은 툴을 쓰기 전에 더 안전한 주문서가 필요한 사용자

### 2차 사용자

- 비개발자가 만든 요구사항을 실제로 구현해야 하는 개발자
- 결과를 검증해야 하는 QA
- 배포와 운영을 맡는 운영 담당자
- Cursor, Claude Code 같은 도구로 빠르게 구현하지만 설계 리스크를 놓치기 쉬운 팀

### 제품 역할

- 비개발자의 아이디어를 개발팀이 바로 실행할 수 있는 요구사항으로 번역합니다.
- 기획 문장, 보안 설계, 구현 티켓 사이의 간극을 줄입니다.
- “막연한 앱 아이디어”와 “실행 가능한 보안 요구사항” 사이의 번역 레이어로 동작합니다.

## 현재 제품 흐름

1. `홈`
   - 제품 소개와 진입 버튼을 보여줍니다.
2. `바로 시작`
   - 아이디어, 보조 질문, 사용할 툴, 기술 스택을 입력합니다.
3. `기본 분석`
   - `A. 뭐가 위험한가?` / `B. 어떻게 바꿀까?` 두 탭으로 위험 분석과 개선 가이드를 나눠 보여줍니다.
4. `심층 보안 분석 리포트`
   - 필요할 때만 잠금 해제해서 더 깊은 보안 설계 리뷰와 개발 실행 티켓을 생성합니다.
5. `업종별 예시`
   - 업종 예시를 골라 입력 화면으로 바로 가져옵니다.
6. `역할별 주의사항`
   - 프론트엔드, 백엔드, QA, 운영 관점의 보안 체크 포인트를 따로 정리해 둡니다.

## 기능 정리

### 1. 입력 단계

- 일반인용 / 개발자용 툴 선택
  - 일반인용: `Lovable`, `v0`, `Replit Agent`
  - 개발자용: `Cursor`, `Claude Code`
- 선택한 툴에 맞춘 추천 문구와 프롬프트 스타일 반영
- 기술 스택 선택기
  - 프론트엔드, 백엔드, 외부 연동 기준으로 다중 선택 가능
  - 비워두면 자동 추정
- `더 자세히 물어보기` 아코디언
  - 업종 / 사용자 / 핵심 행동 / 관리자 역할
  - 수집 데이터 / MVP 기능
  - 숨은 설계 리스크 질문
  - 권한, 클라이언트 금지 필드, 남용 가능 흐름, 외부 연동, URL fetch, 멀티테넌트 분리, AI 도구 문맥 사용 여부
- 업종별 예시를 불러와 입력값과 기술 스택을 미리 채우기

### 2. 기본 분석 결과

#### A. 뭐가 위험한가?

- 원래 요청 원문 표시
- 감지된 위험 목록
- 놓치기 쉬운 설계 리스크 목록

#### B. 어떻게 바꿀까?

- 전후 비교 뷰
- 출시 준비도 점수
  - 별 5개 기반 표시
  - 고정 배점 기준과 사유 표시
- 안전한 앱 요약
- MVP 기능 / 제외 기능 분리
- 허용 데이터 / 차단 데이터 분리
- 관리자 권한 가이드
- 역할별 권한 매트릭스
- 클라이언트가 보내면 안 되는 필드
- 남용 / 비용 폭탄 방어 규칙
- 외부 API / 웹훅 신뢰 규칙
- AI 코딩 툴 안전 사용 규칙
- 툴별 실행 프롬프트
- 초보자 테스트 체크리스트
- 최종 주문서 패키지 전체 복사

### 3. 심층 보안 분석 리포트

심층 리포트는 기본 결과와 분리된 2차 분석입니다.

- 잠금 해제형 버튼 UX
- 기본 분석보다 깊은 보안 설계 리뷰
- 선택한 툴과 기술 스택을 반영한 상세 분석
- `PDF로 저장` 버튼
  - 브라우저 인쇄 기반 PDF 저장 흐름

심층 리포트가 포함하는 산출물:

- 심층 평가와 executive summary
- 지금 출시를 막는 차단 이슈
- 가정한 기술 스택과 그 이유
- 핵심 설계 취약점
- 신뢰 경계
- 권한 경계 경고
- 위험한 클라이언트 제어 필드
- 남용 가능한 흐름
- 스택별 구현 가이드
- 구현 통제 설계도
- 공격 시나리오
- 개발자 / QA 검증 체크리스트
- AI 코딩 툴 사용 경고
- 반영한 보안 기준 요약

### 4. 역할별 실행 산출물

심층 리포트 안에서 다음이 같이 생성됩니다.

- 역할별 실행 요약
  - 프론트엔드
  - 백엔드
  - QA
  - 운영
- 역할별 복사 버튼
- `/roles#...` 앵커 링크로 바로 이동

### 5. 개발자 실행 티켓 자동 생성

심층 리포트 안에서 `실제 작업 단위`로 실행 티켓을 생성합니다.

- 역할별 owner: `frontend`, `backend`, `qa`, `ops`
- 우선순위: `P0`, `P1`, `P2`
- 각 티켓 포함 항목
  - 제목
  - 배경
  - 해야 할 작업
  - 완료 조건
  - 연결 근거
- 개별 티켓 복사
- 전체 티켓 복사
- PDF 저장에도 포함

### 6. 역할별 주의사항 페이지

별도 페이지에서 역할별 보안 체크 포인트를 정리합니다.

- 공통 원칙
- 프론트엔드
- 백엔드
- QA
- 운영 / 배포

### 7. UX / 데모 보강

- 결과 전: 질문 패널 중앙 정렬
- 결과 후: 왼쪽 입력 / 오른쪽 결과 2컬럼 전환
- 부드러운 전환 애니메이션
- 결과 생성 시 미세 강조
- 분석 중 버튼 그라데이션 애니메이션
- 분석 중 텍스트 모션
- 분석 중 프로모 카드 노출
- 최소 5초 로딩 유지

## 사업 모델 가설

현재 제품 구조상 가장 자연스러운 수익화 가설은 다음과 같습니다.

- `무료`
  - 기본 분석
  - 위험 감지
  - 안전한 주문서
  - 툴별 프롬프트
- `유료`
  - 심층 보안 분석 리포트 잠금 해제
  - PDF 저장
  - 역할별 실행 산출물
  - 개발자 실행 티켓 자동 생성
- `팀 / B2B 확장`
  - 비개발 클라이언트와 개발팀 사이를 연결하는 에이전시
  - 개발 외주팀, 교육기관, 내부 보안 검토용 워크플로우
  - AI 기반 사내 프로토타이핑 팀의 사전 설계 검토 도구

## 모델 전략

- 기본 분석: `gemini-3-flash-preview`
- 심층 보안 분석 리포트: `gemini-3-pro-preview`

기본 분석은 속도와 데모 안정성을 우선하고, 심층 리포트는 더 높은 추론 밀도와 구조화 품질을 우선합니다.

## 문제 해결 팁

- `GEMINI_API_KEY is missing` 오류가 나오면 `web/.env.local`을 확인하고 개발 서버를 다시 시작하세요.
- 입력 아이디어가 너무 길고 산만하면 결과가 퍼질 수 있으니, 핵심 사용자와 핵심 행동 중심으로 적는 편이 좋습니다.
- 데모에서는 `/examples`에서 예시를 불러온 뒤 조금만 수정해서 실행하면 더 안정적입니다.
- 심층 보안 리포트는 `pro` 모델을 쓰기 때문에 기본 분석보다 느릴 수 있습니다.
- `PDF로 저장`은 브라우저 인쇄 기반이므로, 팝업 차단이 켜져 있으면 먼저 허용이 필요할 수 있습니다.
